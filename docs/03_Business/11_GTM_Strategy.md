# 11 — Go-to-Market Strategy

> 状态：Decision v1 + GTM Assumptions v1  
> 决策日期：2026-08-11  
> 阶段：GTM & Validation Design Phase  
> 文档角色：定义如何以最低成本获得、激活并留住第一批交易活跃 Creator  
> 核心问题：如何启动 Creator Supply，并通过 Creator 自有流量产生第一批真实交易？

## 1. Purpose

本文件不是传统营销计划，也不以品牌曝光、注册量或平台流量为主要目标。

它负责定义：

- GTM Thesis；
- Initial Market Entry；
- Creator ICP 与优先细分；
- Creator Value Proposition；
- Creator Acquisition Channels；
- Concierge Onboarding；
- Creator Distribution；
- Fan Acquisition；
- Creator Referral；
- Initial Cohort；
- GTM Funnel；
- CAC Measurement；
- Channel Experiment；
- GTM Decision 与 Revisit Trigger。

GTM 的首要任务是：

> 找到并激活能够发布真实供给、主动分发页面并产生第一笔交易的 Creator。

## 2. GTM Thesis

第一阶段 GTM 模型是：

```text
Founder / Community acquires Creator
→ Concierge helps Creator publish
→ Creator distributes Storefront
→ Existing audience takes commercial action
→ Creator receives revenue
→ Creator publishes again
→ Creator refers another Creator
```

当前不是：

```text
Platform buys consumer traffic
→ Consumer discovers Creator
→ Marketplace transaction
```

第一阶段增长依赖三个条件：

1. Creator 已经拥有可触达的受众或客户；
2. Creator 愿意分发自己的商业页面；
3. 页面能够将已有注意力转化为商业行为。

因此 GTM 的核心不是 Buyer Acquisition，而是：

> Creator Supply Acquisition + Creator Distribution Enablement

## 3. GTM North Star

第一阶段 GTM North Star 是：

> Transaction Active Creator：在定义周期内至少拥有一笔已确认付费交易的 Creator。

如果首轮因支付方案尚未上线，则使用临时代理指标：

> Confirmed Commerce Creator：至少拥有一项被 Creator 确认的真实报名、预订、预约或商业需求。

代理指标必须在支付能力就绪后替换，不能永久代替真实交易。

不使用以下指标作为 GTM North Star：

- 注册 Creator；
- Profile Completed；
- Creator Published；
- 页面访问；
- 链接点击；
- 社交账号粉丝数。

这些都是漏斗指标，但不代表商业价值已经发生。

## 4. Initial Market Entry

### 4.1 Primary Market

主市场：

> 拥有独立商业意图、至少一种近期可售供给，并能触达现有受众的舞者。

首轮不以“所有舞者”为目标，而选择最容易形成第一笔 Commerce 的供给。

### 4.2 Geographic Strategy

首轮优先采用：

> One City / One Dense Community

而不是同时覆盖全国。

原因：

- 线下活动与服务受 Location 约束；
- 创始团队需要参与 Concierge Onboarding；
- 同城舞圈、工作室和活动具有关系密度；
- 便于观察真实履约；
- 便于建立 Creator Referral；
- 能降低差旅和运营成本。

首发城市尚未冻结，应根据创始团队可触达网络选择，而不是单纯根据城市规模选择。

城市选择标准：

1. 创始团队是否能直接触达 10–20 位舞者；
2. 是否有活跃舞团、工作室、赛事或活动；
3. 是否有近期真实课程、演出和合作；
4. 是否方便观察线下履约；
5. 是否存在可合作的社区组织者；
6. 是否能够在 30 天内产生真实交易样本。

### 4.3 Initial Commerce Focus

GTM 不同时推广所有 Primitive。

优先寻找拥有以下供给之一的舞者：

1. 即将发生的 Workshop / Event；
2. 可预约的私教 / Service；
3. 明确名额的 Experience；
4. 近期商演或 Content 需求入口。

最优样本拥有两个 Primitive，例如：

- Workshop + 私教；
- 演出 + 粉丝体验；
- 私教 + 商演 Inquiry。

## 5. Creator ICP

### 5.1 Core ICP

首批 Creator ICP：

| 维度            | 优先条件                             |
| --------------- | ------------------------------------ |
| Identity        | 以个人身份被受众识别                 |
| Supply          | 未来 30 天内存在真实可售供给         |
| Commerce        | 已经通过私信、微信或群聊处理商业需求 |
| Autonomy        | 能自行决定至少一个商品、价格或档期   |
| Audience        | 拥有一个可直接触达的真实渠道         |
| Distribution    | 愿意分享链接、二维码或图片           |
| Product Breadth | 最好拥有两种潜在商品                 |
| Learning        | 愿意接受 Concierge 并提供反馈        |

### 5.2 Disqualifiers

首轮不优先：

- 没有近期供给；
- 完全由机构控制商业决策；
- 只希望增加粉丝，不希望交易；
- 无法或不愿分享页面；
- 需要复杂票务、门店 ERP 或完整 B2B 合同；
- 高风险 Experience；
- 无法明确履约责任；
- 只愿建立静态作品集。

### 5.3 ICP Score

每个 Prospect 可使用 0–2 分快速评分：

| 指标       | 0    | 1    | 2           |
| ---------- | ---- | ---- | ----------- |
| 近期供给   | 无   | 模糊 | 30 天内明确 |
| 商业自主权 | 无   | 部分 | 可自行决策  |
| 自有渠道   | 无   | 弱   | 可直接触达  |
| 分享意愿   | 不愿 | 未知 | 明确愿意    |
| 商品数量   | 无   | 1 类 | 2 类以上    |
| 交易历史   | 无   | 偶发 | 已持续发生  |

总分：

- 9–12：Priority A；
- 6–8：Priority B；
- 0–5：暂不进入。

该分数用于安排 Founder 时间，不是 Creator 质量评级。

## 6. Creator Segmentation

### 6.1 Independent Dance Teacher

典型供给：

- 私教；
- 小班课；
- Workshop；
- 编舞指导。

GTM 优势：

- 交易频率较高；
- 供给和价格容易表达；
- 已有学员群；
- 容易产生 Repeat Supply。

风险：

- 可能更需要排课工具；
- 如果依赖舞室，个人商业身份价值可能较弱。

当前优先级：**Tier A**

### 6.2 Multi-hyphenate Dancer

同时从事：

- 教学；
- 演出；
- 约拍；
- 商业合作；
- 内容创作。

GTM 优势：

- 最能验证 Multi-product Commerce；
- 商业身份价值强；
- 可验证多个需求方。

风险：

- Onboarding 较复杂；
- 首版不能承接全部流程。

当前优先级：**Tier A**

### 6.3 Social Dance Creator

在抖音、小红书、B站等拥有内容受众。

典型供给：

- Workshop；
- Experience；
- Event；
- 品牌 Inquiry。

GTM 优势：

- 自带流量；
- 分享和转化实验价值高；
- 页面传播更容易。

风险：

- 粉丝量不等于购买意愿；
- 可能更关注内容合作而非直接 Commerce。

当前优先级：**Tier A / B**

### 6.4 Commercial Performance Dancer

典型供给：

- 商演；
- 活动；
- MV / 品牌拍摄；
- 现场出席。

GTM 优势：

- 高客单；
- B2B Inquiry 价值高；
- 能验证 Availability 和 Capability。

风险：

- 交易非标准；
- 成交周期长；
- 可能依赖经纪人或圈内关系。

当前优先级：**Tier B**

### 6.5 Dance Crew Member

典型供给：

- 团体演出；
- Workshop；
- 粉丝活动；
- 个人教学。

GTM 优势：

- 社群密度高；
- 可形成批量 Creator Acquisition；
- 容易产生 Referral。

风险：

- 团体与个人身份边界；
- 商业自主权可能不清晰。

当前优先级：**Tier B**

### 6.6 Event / ACG Dancer

包括漫展舞者、随机舞蹈或二次元相关舞者。

典型供给：

- Event；
- Experience；
- 约拍；
- Fan Interaction。

GTM 优势：

- Fan Commerce 明显；
- 线下活动传播自然；
- 与 Cosplayer 对照组相邻。

风险：

- 活动周期；
- 安全和未成年人边界；
- 可能被垂直活动平台吸收。

当前优先级：**Tier B**

### 6.7 Institutional Instructor

完全依附舞蹈工作室或机构的老师。

GTM 优势：

- 供给稳定；
- 学员明确。

风险：

- 商业身份和客户关系属于机构；
- 需要门店、排课、员工和分账能力。

当前优先级：**Tier C**

## 7. Creator Value Proposition

### 7.1 External Message

不使用：

- Personal Commerce Infrastructure；
- Creator OS；
- Commerce Primitive；
- Creator Inventory。

这些是内部战略和产品语言。

首轮 Creator Value Proposition：

> 把你散落在抖音、小红书、B站、微信和群聊里的活动、课程、私教与合作信息，整理成一个可以直接分享、预约和成交的个人商业主页。

更短表达：

> 一个页面，集中展示你的行程、课程、预约和合作。

结果导向表达：

> 少重复回复一点，多成交一点。

### 7.2 Value Proposition by Segment

| Segment                | 主要信息                                 |
| ---------------------- | ---------------------------------------- |
| 舞蹈老师               | 把课程和私教统一成可分享的预约页         |
| Multi-hyphenate Dancer | 把演出、教学和合作放进同一个商业主页     |
| Social Dance Creator   | 让粉丝知道你接下来在哪里，以及可以买什么 |
| 商演舞者               | 让活动方快速了解能力、档期和合作方式     |
| 舞团成员               | 建立属于个人、可跨平台使用的商业身份     |

### 7.3 Proof Before Promise

早期不承诺：

- 一定增加收入；
- 自动获得客户；
- 平台提供大量流量；
- 自动处理所有经营问题。

早期承诺应是：

- 帮你整理；
- 帮你发布；
- 帮你形成可分享入口；
- 帮你记录真实商业动作；
- 与你一起验证哪种商品最容易成交。

## 8. Creator Acquisition Channels

### 8.1 Channel Evaluation

渠道不按 Leads 数量排序，而按以下结果排序：

```text
Prospect
→ Creator Published
→ Creator Distributed
→ Transaction Active Creator
→ Repeat Supply
```

每个渠道必须记录：

- Prospect 数；
- Qualified 数；
- Published 数；
- Distributed 数；
- Commerce Activated 数；
- Transaction Active 数；
- Repeat Supply 数；
- Creator Referral 数；
- 现金成本；
- 人工时间；
- CAC。

### 8.2 Direct Founder Outreach

方式：

- 社交平台私信；
- 微信介绍；
- 线下认识；
- 朋友转介绍；
- 针对近期活动的定向邀请。

优势：

- 快；
- 可精准选择 ICP；
- 反馈质量高；
- 适合 Concierge。

风险：

- 人工密集；
- 难以直接规模化；
- 创始人个人网络可能产生样本偏差。

阶段：**第一优先**

### 8.3 Creator Community

目标：

- 舞者微信群；
- 舞团社群；
- 同城舞圈；
- 学员社群；
- 二次元舞蹈社群。

方式：

- 社群负责人合作；
- 免费商业主页共建；
- 小型演示；
- 真实案例分享；
- 集中 Onboarding Session。

优势：

- 信任转移；
- 批量触达；
- Referral 潜力；
- 同类反馈密集。

风险：

- 社群规则；
- 群内推广抵触；
- 低质量批量注册。

阶段：**第一优先**

### 8.4 Dance Studios and Crews

合作对象：

- 舞蹈工作室；
- 舞团；
- Workshop 主办方；
- 独立教师组织。

合作价值：

- 为其核心舞者建立个人商业主页；
- 集中展示 Workshop；
- 帮助活动传播；
- 提供二维码和报名入口。

优势：

- 一次获得多个 Creator；
- 真实活动频率高；
- 便于线下观察。

风险：

- 机构可能要求门店或组织功能；
- 个人客户关系归属冲突；
- 产品被拉向 B2B SaaS。

阶段：**第一 / 第二优先**

### 8.5 Events

场景：

- 舞蹈比赛；
- Workshop；
- Live；
- 漫展；
- 随机舞蹈；
- 城市舞蹈活动。

方式：

- 现场 Concierge；
- 二维码页面；
- Creator 活动页；
- 活动后复盘；
- 现场招募。

优势：

- 供给和需求同时真实存在；
- 时间紧迫，容易测试；
- 能观察完整履约。

风险：

- 活动型样本偏差；
- 交易集中；
- 现场运营成本。

阶段：**第一 / 第二优先**

### 8.6 Creator Referral

方式：

- 每位成功 Creator 邀请 1–2 位同行；
- 分享自己的页面案例；
- Creator 对 Creator 的可信推荐；
- 小型共同活动。

优势：

- 低现金 CAC；
- 信任高；
- 容易进入同一圈层；
- 可能形成局部供给密度。

风险：

- 在 Creator 获得价值前不会自然发生；
- 激励可能带来低质量推荐。

阶段：**交易发生后立即测试**

### 8.7 Content-led Acquisition

内容方向：

- 舞者商业主页案例；
- “如何整理自己的课程和合作”；
- Creator 商品示例；
- 真实成交复盘；
- 页面改造前后对比。

优势：

- 可积累；
- 能教育 Creator；
- 有利于后续 Inbound。

风险：

- 首轮速度慢；
- 内容浏览不等于高质量 Creator；
- 容易吸引泛创业或工具受众。

阶段：**辅助渠道**

### 8.8 Paid Acquisition

MVP 阶段不以广告购买 Creator Leads 为主。

只有在以下条件满足后才测试：

- ICP 已稳定；
- Landing Message 已验证；
- Creator Published Rate 可预测；
- Transaction Active Rate 有基础数据；
- CAC 上限可以由贡献毛利推导。

阶段：**暂不进入**

## 9. Channel Priority

| 优先级 | 渠道                   | 主要目标                      |
| ------ | ---------------------- | ----------------------------- |
| P0     | Founder Direct         | 获得首批高质量 ICP 与深度学习 |
| P0     | Existing Introductions | 低信任成本获得真实样本        |
| P1     | Creator Communities    | 验证社群批量获取与信任转移    |
| P1     | Studios / Crews        | 获得供给密度和真实活动        |
| P1     | Events                 | 验证现场供给、分发和交易      |
| P2     | Creator Referral       | 验证价值驱动的有机增长        |
| P2     | Content-led            | 建立案例与 Inbound            |
| P3     | Paid Acquisition       | 只在单位经济清晰后测试        |

## 10. Creator Onboarding Strategy

### 10.1 Onboarding Is GTM

第一阶段不是：

```text
Acquire
→ Send Signup Link
→ Hope Creator Finishes
```

而是：

```text
Acquire
→ Understand Existing Commerce
→ Build First Storefront Together
→ Publish
→ Distribute
→ Observe Transaction
```

Creator Onboarding 同时承担：

- 激活；
- 商品发现；
- Product Research；
- 信任建立；
- 分发准备；
- 实验执行。

### 10.2 Concierge Offer

首轮对 Creator 的具体邀请：

> 把你的主页、近期行程、课程、服务和合作方式发给我们，我们帮你整理成一个可以直接分享的商业主页，并和你一起测试第一笔预约或报名。

### 10.3 Concierge Inputs

Creator 可以提供：

- 社交主页；
- 自我介绍；
- 作品链接；
- 近期行程；
- 课程海报；
- 服务和价格；
- 商演或合作信息；
- 当前报名与联系流程。

团队负责协助提取：

- Identity；
- Capability；
- Upcoming；
- Product；
- Price；
- Availability；
- Commercial Action；
- Rules。

### 10.4 Concierge Session

候选 30–45 分钟流程：

```text
5 min  当前商业行为
10 min 供给和商品梳理
10 min 页面创建
5 min  预览与修正
5 min  发布与分享
5 min  确认后续观察
```

产品成熟后目标是将 Creator 自助发布时间降至约 10–15 分钟。

### 10.5 Concierge Learning Record

每次 Onboarding 必须记录：

- Creator 原本如何表达供给；
- 最常见 Primitive；
- 哪些信息缺失；
- Creator 不愿公开什么；
- 哪些字段需要解释；
- 创建中断点；
- 完成人工时间；
- Creator 是否真实分享；
- 首个商业结果；
- 后续更新行为。

### 10.6 Concierge Exit Criteria

当以下条件成立后，开始降低人工介入：

- 同类 Creator 创建路径高度重复；
- 80% 商品可由稳定模板表达；
- Creator 自助发布率可接受；
- 人工时间不再带来显著额外学习；
- 自助 Creator 的 Distributed 和 Transaction Rate 不显著下降。

## 11. Creator Distribution Strategy

### 11.1 Distribution Thesis

Creator 不是单纯供给方，也是第一阶段的分发渠道。

```text
Creator Publishes
→ Creator Distributes
→ Existing Audience Visits
→ Commercial Action
```

如果 Creator 不分发，Creator-first GTM 不成立。

### 11.2 Distribution Surfaces

不能依赖单一平台简介外链。

首版应支持或运营提供：

- 可复制 URL；
- 二维码；
- 可分享图片；
- Upcoming 海报；
- Product 卡片；
- 微信私聊；
- 微信群；
- 朋友圈；
- 小红书内容或评论引导；
- B站动态或简介；
- 抖音私信、群聊或允许的外链位置；
- 线下海报和活动现场。

具体平台能力可能变化，GTM 必须保持渠道冗余。

### 11.3 Distribution Asset

每个 Storefront 发布后至少生成：

1. 页面链接；
2. 二维码；
3. 一张可直接传播的 Creator 商业卡片；
4. 一个 Upcoming 或 Product 分享素材；
5. 一段 Creator 可修改的分享文案。

这些是 Product / GTM 交界能力，是否进入 MVP PRD 由实验决定。

### 11.4 Share Moment

最佳分享时机不是页面创建完成，而是存在真实供给时：

- 新 Workshop 发布；
- 新城市行程；
- 开放私教档期；
- 新 Experience 名额；
- 新演出或活动；
- 商务档期开放。

因此页面需要持续供给更新，而不是一次性自我介绍。

### 11.5 Distribution Commitment

进入首批 Cohort 的 Creator 应同意：

- 发布后至少分享到一个真实渠道；
- 保持链接或素材可见一个合理周期；
- 允许团队观察来源与商业动作；
- 在交易后反馈结果；
- 不要求提供敏感账号权限。

## 12. Fan Acquisition Strategy

### 12.1 MVP Fan Acquisition

第一阶段不主动购买大规模 Fan 流量。

Fan 来源：

- Creator 自有社交渠道；
- Creator 社群；
- Creator 线下活动；
- Creator 直接发送；
- Partner 活动页面；
- Creator Referral 产生的交叉曝光。

### 12.2 Platform Role

平台负责提高：

- 页面清晰度；
- 供给理解；
- 信任；
- 商业动作完成率；
- 结果确认。

平台暂不负责：

- 推荐 Creator；
- 提供 Feed；
- 搜索全平台；
- 购买广告流量；
- 建立消费者品牌。

### 12.3 Fan Acquisition Cost

MVP 中 Buyer CAC 可能接近零现金成本，但绝不自动等于零。

需要计入：

- Creator 分发激励；
- 分享素材成本；
- Partner Revenue Share；
- 活动现场成本；
- Buyer Support；
- 归因工具成本。

## 13. Creator Referral

### 13.1 Referral Trigger

Creator Referral 应在 Creator 获得可感知价值后触发：

- 页面发布；
- 首个商业动作；
- 第一笔交易；
- 成功履约；
- 收到正向反馈。

其中第一笔交易后是最强时机。

### 13.2 Referral Ask

不使用：

> 邀请朋友注册平台。

使用：

> 如果你身边也有舞者在用私信管理课程、活动或合作，可以介绍给我们，我们也帮 TA 免费整理第一个商业主页。

### 13.3 Referral Incentives

首轮优先非现金价值：

- Concierge 优先；
- 页面优化；
- 分享素材；
- 费率测试优惠；
- 活动案例展示；
- 早期 Creator 身份。

现金或永久佣金只在 Referral 质量和经济模型清晰后测试。

### 13.4 Referral Quality

Referral 仍需通过 ICP Qualification。

核心指标：

- Referred Prospects；
- Qualified Referral Rate；
- Published Rate；
- Transaction Active Rate；
- CAC per Transaction Active Creator。

## 14. Initial Cohort Strategy

### 14.1 Cohort 0 — Design Partners

规模：

- 5–8 位舞者；
- 1–2 位 Cosplayer；
- 1–2 位摄影师。

目标：

- 手工建立页面；
- 收集真实商品；
- 测试语言和 Primitive；
- 完成首次外部分发；
- 观察首个商业动作。

要求：

- 高度 Founder-led；
- 不追求 CAC；
- 记录全部人工步骤；
- 重点是学习速度。

### 14.2 Cohort 1 — Transaction Validation

规模：

- 8–12 位舞者；
- 3–5 位 Cosplayer；
- 3–5 位摄影师。

目标：

- 验证 Creator Published；
- 验证 Creator Distributed；
- 产生至少 10 个有效商业动作；
- 观察真实付款或确认交易；
- 比较 Primitive。

### 14.3 Cohort 2 — Channel Validation

规模：

- 30–50 位 Creator；
- 至少两个 Acquisition Channel。

目标：

- 比较 Direct、Community、Studio、Event；
- 测量 CAC；
- 测量 Transaction Active Rate；
- 测量 Repeat Supply；
- 测试 Creator Referral。

### 14.4 Cohort 3 — Repeatable GTM

进入条件：

- ICP 稳定；
- Value Proposition 稳定；
- Onboarding 路径可重复；
- 至少一个渠道产生可接受的 Transaction Active CAC；
- Creator 30-day Retention 有初始信号；
- 支付和单位经济可测。

此后才考虑 100–1,000 Creator 的规模化路径。

## 15. GTM Funnel

```text
Creator Prospect
→ Qualified Creator
→ Creator Activated
→ Creator Published
→ Creator Distributed
→ Commerce Activated
→ Transaction Confirmed
→ Transaction Active Creator
→ Repeat Supply
→ Retained Creator
→ Creator Referral
```

### 15.1 Creator Prospect

进入 Founder、Community、Partner 或 Referral 渠道的潜在 Creator。

### 15.2 Qualified Creator

满足核心 ICP，拥有近期供给与分发可能。

### 15.3 Creator Activated

Creator 开始 Onboarding 并完成必要信息。

此指标用于识别 Acquisition 到 Setup 的损失，但不是产品 Activation。

### 15.4 Creator Published

拥有公开 Storefront、有效供给和商业动作。

### 15.5 Creator Distributed

将 Storefront 或 Product 素材分享到至少一个真实渠道。

### 15.6 Commerce Activated

获得至少一个可归因商业动作。

### 15.7 Transaction Confirmed

Creator 接受真实订单、预约或报名，或交易完成付款。

### 15.8 Transaction Active Creator

在定义周期内拥有至少一笔已确认付费交易。

### 15.9 Repeat Supply

Creator 创建第二项供给、更新档期或再次分享。

### 15.10 Retained Creator

在 30 / 60 / 90 天周期内持续经营供给或交易。

### 15.11 Creator Referral

Creator 推荐至少一个新的 Qualified Creator。

## 17. CAC Measurement

### 17.1 Fully Loaded Creator CAC

```text
Fully Loaded Creator CAC
= Cash Channel Spend
+ Founder / Sales Time Cost
+ Community / Partner Cost
+ Concierge Onboarding Cost
+ Incentives
+ Attributable Content Cost
────────────────────────────────
New Creators at Funnel Stage
```

分别计算：

- CAC per Qualified Creator；
- CAC per Creator Published；
- CAC per Creator Distributed；
- CAC per Transaction Active Creator。

### 17.2 Shadow Cost

早期创始团队时间需要记录影子成本：

```text
Shadow Labor Cost
= Hours Spent × Assumed Hourly Cost
```

虽然现金未支出，但用于判断渠道是否能规模化。

### 17.3 Channel Attribution

每位 Creator 至少记录：

- First-touch Channel；
- Trust Source；
- Onboarding Owner；
- Distribution Source；
- Transaction Source；
- Referral Source。

不要把所有 Founder Network Creator 记为零 CAC。

### 17.4 CAC Ceiling

规模化前：

```text
Allowable CAC
≤ Expected Creator LTV × Target LTV/CAC Ratio
```

在没有留存与贡献数据时，不冻结 CAC Ceiling。

短期只比较渠道相对效率，并验证基础情景是否可能形成合理 Payback。

## 18. Channel Experiment Candidates

### E-11-01 — ICP Segment

**Hypothesis**：Multi-hyphenate Dancer 与 Independent Dance Teacher 比纯商演舞者更快产生首笔交易。  
**Method**：在相同 Concierge 条件下比较三个 Segment。  
**Primary Signal**：Transaction Active Rate、Time to First Transaction。  
**Guardrail**：控制近期供给是否存在。  
**Decision Use**：冻结首个可重复 ICP。

### E-11-02 — Founder Direct

**Hypothesis**：定向邀请近期有真实供给的舞者，可以产生高 Published 和 Distributed Rate。  
**Method**：招募 20 个 Priority A Prospect。  
**Primary Signal**：Published、Distributed、Transaction Active Rate。  
**Guardrail**：记录 Founder 时间。  
**Decision Use**：判断 Direct Outreach 是否适合 Cohort 1。

### E-11-03 — Community Acquisition

**Hypothesis**：通过可信社群负责人引入的 Creator，拥有更低 CAC 和更高 Activation。  
**Method**：与 2–3 个舞者社群合作。  
**Primary Signal**：Qualified Rate、Published Rate、CAC。  
**Guardrail**：避免无筛选批量注册。  
**Decision Use**：判断 Community-led GTM。

### E-11-04 — Studio / Crew Partner

**Hypothesis**：一个 Studio / Crew 可以产生 5 个以上 Qualified Creator，而不要求门店 SaaS 功能。  
**Method**：与 2 个组织进行批量 Concierge。  
**Primary Signal**：Qualified Creators per Partner、Transaction Active Rate。  
**Guardrail**：记录机构功能请求。  
**Decision Use**：决定 Partner Channel 优先级。

### E-11-05 — Event Acquisition

**Hypothesis**：围绕近期 Event 招募 Creator，可以缩短从 Published 到 Transaction 的时间。  
**Method**：选择 1–2 个真实舞蹈活动或 Workshop。  
**Primary Signal**：Time to First Commercial Action、Transaction Conversion。  
**Guardrail**：观察活动后 Repeat Supply。  
**Decision Use**：判断 Event-led Acquisition 是否只是一次性。

### E-11-06 — Concierge vs Self-serve

**Hypothesis**：Concierge 显著提高 Published 和 Distributed，但人工时间可以逐步由模板降低。  
**Method**：比较全 Concierge、轻 Concierge 和 Self-serve。  
**Primary Signal**：Published Rate、Minutes per Creator、Transaction Active Rate。  
**Guardrail**：不能只比较创建完成率。  
**Decision Use**：确定 Onboarding 模式。

### E-11-07 — Distribution Asset

**Hypothesis**：Product 卡片和二维码比裸链接获得更高的 Creator 分享率。  
**Method**：给不同 Cohort 提供不同分享素材。  
**Primary Signal**：Distributed Rate、Visits per Share。  
**Guardrail**：按渠道区分。  
**Decision Use**：决定分享资产是否进入 MVP。

### E-11-08 — Distribution Channel

**Hypothesis**：微信群、私聊和活动二维码比社交简介链接更快产生首个商业动作。  
**Method**：记录每次分享的渠道与来源。  
**Primary Signal**：Commercial Actions per Visit、Time to First Action。  
**Guardrail**：考虑不同 Creator 受众规模。  
**Decision Use**：确定 Creator Distribution Playbook。

### E-11-09 — Value Proposition

**Hypothesis**：“少管理一点 + 多成交一点”比“统一 Creator 商业身份”产生更高回应和 Onboarding。  
**Method**：测试三组外部信息。  
**Primary Signal**：Response Rate、Qualified Onboarding Rate。  
**Guardrail**：不承诺未经证明的收入增长。  
**Decision Use**：冻结 Creator Acquisition Message。

### E-11-10 — Referral after Value

**Hypothesis**：在首笔交易后邀请推荐，比发布后邀请推荐产生更高质量 Creator。  
**Method**：比较两个 Referral Ask 时机。  
**Primary Signal**：Qualified Referrals、Transaction Active Referral Rate。  
**Guardrail**：不使用高额现金激励。  
**Decision Use**：建立 Referral Loop。

## 19. GTM Decision Record

### D-11-01 — Supply-first GTM

**Decision**：第一阶段 GTM 以 Creator Supply Acquisition 为核心，不主动建设消费者 Marketplace。  
**Reason**：Creator 自带第一批受众，可以避免双边冷启动。  
**Revisit Trigger**：Creator 自有流量无法产生有效需求，或平台出现稳定自然买方流量。

### D-11-02 — GTM North Star

**Decision**：GTM North Star 是 Transaction Active Creator。  
**Reason**：Transaction-first 商业模型要求 GTM 最终产生真实交易。  
**Revisit Trigger**：SaaS 成为首要商业模式，或交易无法在合理周期内观测。

### D-11-03 — Primary ICP

**Decision**：优先获取拥有近期供给、自主商业决策和自有渠道的独立舞者。  
**Reason**：这类 Creator 最有可能快速 Published、Distributed 并成交。  
**Revisit Trigger**：其他舞者 Segment 显著拥有更高 Transaction Active Rate。

### D-11-04 — Geographic Focus

**Decision**：首轮采用 One City / One Dense Community。  
**Reason**：提高信任、供给密度和线下观察效率。  
**Revisit Trigger**：创始团队的有效网络天然跨城市，且远程履约数据足够可靠。

### D-11-05 — Acquisition Channels

**Decision**：优先 Founder Direct、Existing Introductions、Creator Community、Studio / Crew 和 Event；暂不依赖 Paid Acquisition。  
**Reason**：早期需要高质量样本和深度学习，而不是 Lead 数量。  
**Revisit Trigger**：ICP 与经济模型稳定，能够计算可接受 CAC。

### D-11-06 — Concierge Onboarding

**Decision**：Cohort 0–1 使用 Concierge Onboarding。  
**Reason**：帮助 Creator 成功，同时收集商品与流程数据。  
**Revisit Trigger**：人工不再产生学习，或人工成本阻断 Cohort 扩张。

### D-11-07 — Creator Distribution

**Decision**：Creator Published 后必须推动 Creator Distributed；不依赖单一平台简介外链。  
**Reason**：Published 不产生需求，且平台渠道规则可能变化。  
**Revisit Trigger**：平台自身开始持续提供增量需求。

### D-11-08 — Fan Acquisition

**Decision**：MVP Fan 流量来自 Creator 与 Partner 自有渠道，不购买大规模消费者流量。  
**Reason**：先验证 Storefront 对已有商业意图的转化。  
**Revisit Trigger**：Creator-owned Demand 不足，且单位经济允许购买需求。

### D-11-09 — Referral Timing

**Decision**：Creator Referral 在 Creator 获得可感知价值后触发，优先在首笔交易或履约后。  
**Reason**：价值驱动的推荐质量高于注册激励。  
**Revisit Trigger**：发布后 Referral 已能稳定产生高质量 Creator。

### D-11-10 — Channel Evaluation

**Decision**：渠道按 CAC per Transaction Active Creator 和 Repeat Supply 评估，不按注册量评估。  
**Reason**：渠道必须产生持续商业供给。  
**Revisit Trigger**：商业模式从交易转为纯 SaaS。

## 20. GTM Revisit Triggers

### ICP

- 舞者普遍没有独立商业自主权；
- 30 天内真实供给不足；
- 摄影师或 Cosplayer 的 Transaction Active Rate 显著更高；
- 最强 Segment 只需要单点排课或票务。

### Acquisition

- Direct Outreach 响应低且无法通过 Message 改善；
- Community 和 Studio 带来大量不合格 Creator；
- Founder Time 无法随模板下降；
- Paid Acquisition 的早期测试反而拥有更低有效 CAC。

### Distribution

- Creator Published 但不愿分享；
- 平台限制导致链接和二维码无法传播；
- Storefront Visits 有但商业动作低；
- Creator 只在一次活动中使用页面。

### Commerce

- 大部分 Creator 无法在 30 天内产生确认交易；
- 交易高度依赖团队人工销售；
- Creator 自有流量不能带来真实购买；
- Inquiry 显著强于 C 端 Commerce。

### Retention

- 首笔交易后无 Repeat Supply；
- Creator 将复购迁移到平台外；
- 30-day Retention 低且与交易结果无关；
- Referral 无法在价值发生后形成。

## 21. GTM Non-goals

MVP GTM 明确不做：

- 全国性品牌投放；
- 大规模消费者获客；
- Creator Marketplace 冷启动；
- 广泛招募所有 Creator；
- 以注册数制造增长；
- 无筛选的免费活动；
- MCN 大客户销售；
- 复杂渠道分销体系；
- 永久现金 Referral；
- 大额 Creator 补贴；
- 购买虚假交易；
- 依赖单一社交平台外链；
- 在单位经济未知时扩大 Paid Acquisition；
- 在一个城市尚未跑通前同时进入大量城市；
- 为 Partner 承诺门店 ERP 或机构管理功能。

## 23. Frozen GTM Strategy

> MVP GTM 以 Creator Supply 为起点，优先在一个创始团队可深度触达的城市和舞者社区中，寻找拥有近期供给、独立商业决策权和自有受众渠道的舞者。第一批 Creator 通过 Founder Direct、Existing Introductions、Creator Communities、Studios / Crews 和真实 Events 获得，并使用 Concierge Onboarding 完成首个 Storefront。

> Creator Published 不是 GTM 成功。Creator 必须进一步 Creator Distributed，将链接、二维码或商品素材分享到真实渠道；Fan 和 Customer 由 Creator 自有流量进入，并完成商业动作。GTM North Star 是 Transaction Active Creator，渠道按 CAC per Transaction Active Creator、Repeat Supply 和 Creator Retention 评估。

> 第一阶段不购买大规模消费者流量，不建设 Marketplace，不以注册量优化增长。增长闭环是 Creator 获得交易价值后持续更新供给，并将其他合格 Creator 推荐进入产品。

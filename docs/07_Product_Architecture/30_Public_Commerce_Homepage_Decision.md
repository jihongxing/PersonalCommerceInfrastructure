## 1. 产品问题与目标

创作者在外部平台传播 C 号后，访客需要无需登录即可找到对应的商业主页。一个 Internal Identity
对应一个终身不变的 C 号，并对应一个稳定的公开主页地址 `/r/{C号}`。主页资料和已发布服务可
随时间变化；变更公开资料、服务或登录方式不得改变 C 号及其主页地址。此规则沿用 DEV-061，
不把 Account、Identity、Commerce Profile 和 Creator 业务标识视为同一个对象。

## 2. 创作者与访客流程

1. 注册成功后系统按 DEV-061 初始化 Identity 和 C 号；初始化失败时沿用 `setupPending` 与可
   重试语义，不虚称号码已分配。获得 C 号本身不会公开任何资料。
2. 创作者选择该 Identity 允许公开的资料，完善资料并主动发布主页；工作台显示未发布、已发布
   或暂停，提供预览、发布、暂停和复制主页链接，并提供基于同一链接的二维码。
3. 公开查询页面允许访客输入或粘贴带连字符或不带连字符的 C 号，校验并规范化后访问对应
   `/r/{C号}`；二维码扫描直接打开同一个规范主页地址。访客无需登录。
4. 公开主页仅展示创作者选定的公开资料和已发布服务；只有满足现有请求条件的服务提供可操作
   请求入口。注册邮箱、未选择公开的资料以及草稿、下架或归档服务不得因获得 C 号而公开。
   主页可以在没有已发布服务时发布，此时服务区显示“尚无服务”；最后一个服务下架后主页保持
   发布并显示相同空态。
5. 编辑内容或切换该 Identity 已授权的公开资料不改变主页地址。暂停后访客不能看到主页内容；
   创作者经授权可预览。未发布、暂停、号码不存在可对外统一显示主页不可访问，避免泄露不必要
   的状态；格式错误与系统故障须可区分，故障提供重试。

## 3. 身份与信任边界

- 公开解析为 `C号 → Identity → 创作者选定的公开资料 → 已发布服务`。一个 Identity 可以有
  多个 Commerce Profile，主页选择必须验证归属、生命周期和访问权限；不得枚举全部 Profile
  或从旧号码记录的历史 Profile 外键推断公开选择。
- C 号是公开引用，不是认证凭据、授权依据、所有权证明或公域平台账号的身份验证。任何人都
  可以复制号码或二维码；平台账号验证须另行设计。
- 预览与管理必须由服务端验证当前账号对 Identity 的权限；前端隐藏按钮不构成授权。公开接口
  只返回明确允许的字段，故障不得伪装为不存在或未发布。

## 4. 已确认的范围和不变量

本决策覆盖访客查询、稳定链接、二维码、创作者主页管理和公开解析；不引入平台账号验证、支付、
Marketplace 或 CRM。二维码与链接的生成或复制不等于真实外部分发，也不自动产生分发事实。
已有预约及历史商业动作不能因主页暂停或资料变更而被删除或篡改。

既有 C 号登记簿及其不变性、不可转让和不可复用约束继续生效；不能为了主页重新发号。分享的
规范路径使用 18 位大写无分隔符的 C 号，界面仍可使用 `XXXXXX-XXXXXX-XXXXXX` 展示。输入
规范化只能接受已有字符集和明确支持的分隔形式，不能静默纠正其他字符或匹配错误号码。

## 5. 发布状态与规范事件

2026-11-08，Founder 明确允许无已发布服务的主页展示空态，并授权确定状态和事件细则。作出
以下决策；对应的正式合同增补见 [VS-01 PRD 的 DEV-062 修订](./20_MVP_PRD_VS01.md#dev-062-amendment--c-号公开商业主页)。

| 概念              | 状态和行为                                                                                                                                                                                                           |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C 号主页          | 独立的未发布、已发布、暂停状态。已分配 C 号且已选择合法、归属正确、具备最小公开展示信息的资料时，创作者可主动发布；不要求已有已发布服务。未发布 → 已发布 → 暂停 → 已发布，重复命令幂等，非法或无权限操作不改变状态。 |
| Commerce Identity | 保留既有 Draft / Published / Unpublished 状态和与合格 Offering 发布、撤下有关的规则；它不是主页发布状态。主页的发布或暂停不直接更改该状态。                                                                          |
| Offering          | 保留原有生命周期与请求条件。主页发布或暂停不更改服务状态；服务发布或最后一个服务下架不改变主页状态。已发布主页仅展示符合公开条件的已发布服务；没有时显示“尚无服务”。                                                 |

主页暂停只关闭通过该主页的公开访问，不撤下独立服务链接，不改变服务请求资格，也不删除历史
请求。独立服务链接仍按原有 Identity、Offering 和可请求条件决定可用性；若需同时关闭服务，
创作者需通过服务管理操作。重新发布主页不自动重发服务或生成新的 C 号。

`creator_published` 保留首次合格 Offering 使既有 Commerce Identity 首次 Published 的事实；
仅发布、暂停或恢复 C 号主页不产生该事件，主页可先于此事件公开。`storefront_viewed` 记录
访客成功打开已发布的 C 号主页或既有公开服务入口的事实；授权预览、后台编辑、格式错误、
不可访问和加载失败均不产生该事件。同一次 HTTP 请求或一次页面视图不得重复记录同一事实；
访客之后独立打开服务详情属于另一页面视图。记录该事件不要求已发布服务存在。

主页发布、暂停、恢复和资料选择需要可审计的业务状态变更记录，但本决策不新增 Canonical Event；
技术审计不得冒充上述规范事件。链接/二维码生成、复制和预览不触发 `creator_distributed`。
多 Profile 与历史本地 Creator 数据的实际关联、最小公开字段和迁移处理仍须实施盘点；关联无法
证明时不得猜测归属或自动公开。执行台账和实施计划不代表功能已实现。

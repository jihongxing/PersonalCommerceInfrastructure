# 34 — 受控能力目录与服务发布决策

> 日期：2026-11-10  
> 变更单元：DEV-082 / CONTROLLED-CAPABILITY-AND-SERVICE-PUBLISHING  
> 状态：Founder 已批准产品方向；实现已完成，产品验收待确认
> 适用范围：Creator Capability、Service Offering、公开主页与服务发布  
> 上游合同：[20 - MVP PRD: VS-01](./20_MVP_PRD_VS01.md)  
> 执行记录：[21 - Prototype Execution](../08_Execution/21_Prototype_Execution.md)

## 1. 决策摘要

Personal Commerce Infrastructure 允许 Creator 表达能力并发布服务，但不把平台当作
任意内容编辑器。能力和服务一旦进入公开主页、稳定分享和 Customer Request 流程，平台
就承担可解释的供给边界和发布责任。

本决策批准以下产品方向：

```text
平台能力目录
→ Creator 选择并声明能力
→ 选择与能力匹配的服务模板
→ 填写结构化服务条件和有限补充说明
→ 自动规则检查
→ 必要时人工审核
→ 通过发布门禁后公开和分享
```

Creator 可以自由表达经验、作品、风格和履约细节，但不能直接创建可公开发布的能力
类别或任意服务类型。自定义类别只能进入新增目录申请，不得作为绕过政策的发布入口。

## 2. 背景与问题

现有产品模型正确区分了 `Capability` 与 `Service Offering`：Capability 表达 Creator
具备的商业能力，Offering 表达可被请求的具体供给。当前 VS-01 还允许 Creator 最小化
创建或关联 Capability，并基于它创建 Service Offering。

如果能力名称、服务标题和服务内容都完全由 Creator 自由定义，会产生以下问题：

1. 平台无法建立稳定的能力语义和服务字段；
2. 规避词、暗语或模糊描述可以绕过简单关键词过滤；
3. 公开主页和分享链接会成为高风险服务的分发入口；
4. 服务无法统一判断对象、交付范围、地点、时长和安全条件；
5. 举报、下架、申诉和重复审核没有一致的政策依据。

现有产品定义已经排除开放式陌生人社交、未定义边界的私人陪伴和平台无法合理控制的
高风险线下互动。本决策把这些边界转化为创建和发布流程中的可执行门禁。

## 3. 核心原则

### 3.1 平台控制语义，Creator 控制表达

平台控制：

- 能力目录及其版本；
- 服务模板及必填字段；
- 禁止和需审核的服务类型；
- 发布资格和风险状态；
- 举报、暂停、复核和申诉规则。

Creator 控制：

- 个人经验和作品证明；
- 教学或服务风格；
- 服务参数中的可选内容；
- 价格、时间、地点和可接受的履约条件；
- 经模板允许的补充说明。

### 3.2 结构化优先，自由文本补充

服务能否发布不能只依赖标题和长文本。服务必须先具备结构化的目标、形式、时长或
交付范围、地点或线上方式、参与人数、前置条件和确认规则，再允许 Creator 增加补充
说明。

### 3.3 风险判断针对完整服务上下文

风险检查不能只检查能力名称。至少需要联合判断：

- 服务对象和年龄条件；
- 是否一对一、上门或私密地点；
- 是否涉及身体接触或人身安全；
- 是否作出医疗、金融、法律或收益保证；
- 是否要求绕开平台的私下支付或联系；
- 是否存在违法、欺诈、性化或其他受禁止的目的。

### 3.4 发布资格与业务生命周期分离

现有 `Draft / Published / Unpublished` 表示 Creator 对 Offering 的业务操作。
政策审核状态是另一条正交轴，不能覆盖或伪装成 Creator 的业务状态。

## 4. 目录和模板模型

### 4.1 平台能力目录

平台维护版本化的 `CapabilityCatalogItem` 目录项。它是平台政策参考数据，不等于
Creator 的 Capability 产品对象，也不改变现有 Creator 所有权模型。

目录项至少包含：

- 稳定标识和显示名称；
- 所属垂直领域；
- 允许关联的服务模板；
- 风险等级；
- 必要证明或附加信息；
- 禁止的上下文；
- 政策版本和生效时间；
- `active`、`review` 或 `retired` 状态。

Creator 保存的是 `CreatorCapability`，并引用一个有效的目录项。Creator 的经验、作品
和证明仍是自我声明，除非另有验证，不得显示为平台认证或资质背书。

### 4.2 服务模板

平台维护版本化的 `ServiceOfferingTemplate`。模板定义：

- 可关联的能力目录项；
- 服务类型的公开名称；
- 必填和可选字段；
- 允许的履约方式；
- 风险规则和需要人工审核的条件；
- 发布前需要的提示和确认；
- 政策版本。

模板和目录项是政策和产品配置，不自动成为新的公开商业对象。对外仍由现有
`Service Offering` 承载可请求供给。

### 4.3 VS-01 首期范围

VS-01 继续保持 Dancer Private Lesson Request 的窄范围。首期可公开发布的目录和模板为：

```text
能力目录：舞蹈教学
服务模板：1 对 1 舞蹈私教
```

小班课程、编舞指导、商业演出、内容合作和其他垂直服务保留为后续候选，必须经过
独立的产品范围和政策决策后才能加入可发布目录。策略机制可以提前设计，不能借此
扩大 VS-01 的当前商业流程。

## 5. 风险分级与发布门禁

### 5.1 风险等级

| 等级 | 典型范围 | 默认处理 |
| --- | --- | --- |
| Low | 舞蹈教学、编舞指导、明确交付的创作辅导 | 自动规则检查通过后可发布 |
| Review | 上门服务、未成年人、一对一线下、身体接触、跨城市出行 | 转人工审核或要求附加信息 |
| Prohibited | 私人陪伴、性化服务、违法交易、赌博、毒品、武器、无资质受监管服务、欺诈承诺 | 拒绝发布 |

风险等级是目录和模板的默认值。服务上下文触发更高风险规则时，服务必须升级处理，
不能因为能力目录本身是 Low 就直接放行。

### 5.2 发布资格

公开发布必须同时满足：

```text
businessStatus = Published
policyStatus = Approved
creator owns capability and offering
required fields are complete
request conditions are valid
```

建议的政策状态为：

```text
NotChecked
→ AutoApproved
→ ReviewRequired
→ Approved / Rejected
```

已发布服务被举报、政策升级或修改后重新触发风险条件时，可以进入 `ReviewRequired`
并被暂停公开。暂停、拒绝和恢复必须保留原因、政策版本、操作者和时间。

### 5.3 禁止绕过目录和模板

以下路径不允许直接公开：

- 自定义能力名称作为新的目录类型；
- “其他服务”作为无模板发布入口；
- 仅通过长文本说明服务内容；
- 以外部联系方式或私聊承诺替代服务条件；
- 通过改标题、谐音或暗语规避审核。

Creator 找不到匹配类型时，只能提交“申请新增能力或服务类型”。申请通过前，内容
保持草稿或不可公开状态。

## 6. 创建、审核和运营流程

### 6.1 Creator 创建流程

```text
选择能力目录项
→ 补充经验、作品和证明
→ 选择允许的服务模板
→ 填写结构化服务条件
→ 填写有限补充说明
→ 自动规则检查
→ 自动通过或进入人工审核
→ 预览并发布
```

### 6.2 编辑和重新审核

以下变更必须重新检查：

- 能力目录项；
- 服务模板；
- 服务目标和交付范围；
- 地点、线上方式或上门条件；
- 年龄、参与人数或身体接触相关条件；
- 标题和补充说明中的关键文本。

普通拼写修正是否重新审核由模板定义，但不能通过拆分编辑逃避检查。重新审核期间，
原有已发布版本可以按政策保留或暂停，具体规则必须在模板中声明。

### 6.3 举报、暂停和申诉

平台需要提供：

- 公开服务举报入口；
- 受理、暂停、复核和恢复记录；
- 创作者可读的拒绝原因；
- 申诉和人工复核入口；
- 对重复违规内容和账号的升级处理。

自动分类或语言模型只能辅助排序和提示，不能单独成为高风险拒绝的唯一证据。最终
政策结果必须可追溯到明确规则和人工决定，或记录自动规则的版本。

## 7. 对现有产品合同的影响

本决策改变了现有 Capability 创建、Service Offering 创建和 Offering Publish 的
产品行为，属于产品影响变更，不能直接作为普通前端改造实施。

实现前必须修订或补充：

1. `17_Core_Product_Objects.md`：明确 Creator Capability 与平台目录项的关系；
2. `18_MVP_Product_Flow.md`：加入选择目录、模板和发布检查的分支；
3. `19_MVP_Product_Specification.md`：补充创建、审核、拒绝、申诉和暂停状态；
4. `20_MVP_PRD_VS01.md`：更新 FR-003、FR-006 至 FR-013 及相关验收边界；
5. API 合同：服务端执行目录、模板、归属和政策状态检查；
6. 数据迁移：现有自由文本能力和服务必须映射、进入草稿或人工复核，不能静默视为已批准；
7. 测试：增加安全边界、编辑重审、公开过滤、拒绝、举报和申诉覆盖。

本决策不授权：

- Payment、Settlement、Refund 或真实货币能力；
- Marketplace、Search、Discovery 或推荐；
- 完整职业资格认证或平台背书；
- AI 自动审核作为唯一政策决策；
- 未经独立决策的新增垂直服务；
- 新的规范事件名称。

## 8. 产品验收标准

实现完成前，至少需要证明：

1. Creator 不能把任意自定义能力类别直接发布到公开主页；
2. Service Offering 必须引用有效能力目录项和服务模板；
3. 缺少必填交付条件的服务不能发布；
4. 低风险服务可以通过自动检查并发布；
5. 模糊或中风险服务进入人工审核，不会静默公开；
6. 禁止服务无法通过 API 或前端绕过发布门禁；
7. 关键服务字段变更会重新触发检查；
8. 公开主页只展示已发布且政策状态为 `Approved` 的服务；
9. 举报、暂停、拒绝、申诉和恢复均有可追溯记录；
10. 现有服务和请求历史在迁移后不被静默删除或改变归属；
11. 现有 VS-01 Request、Confirm / Decline 和 Canonical Event 语义保持不变，除非另有批准的 PRD 修订。

## 10. 决策结果

本决策批准“受控能力目录 + 服务模板 + 风险分级发布”的产品方向，作为后续 PRD
修订和实现的上游依据。DEV-082 在完成产品合同修订、实现、测试和验收前保持开放，
不因本文档创建而标记为完成。

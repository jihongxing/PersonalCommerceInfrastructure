# 35 — 数据库管理的能力与服务目录决策

> 日期：2026-11-11  
> 变更单元：DEV-083 / DATABASE-MANAGED-CAPABILITY-AND-SERVICE-CATALOG  
> 状态：Founder 已批准；实现完成，聚焦验证待记录  
> 上游决策：[34 — 受控能力目录与服务发布决策](./34_Controlled_Capability_Service_Publishing_Decision.md)

## 1. 决策

能力目录和服务模板是平台政策配置，运行时以数据库中当前发布的目录版本为唯一来源。
JSON 只作为初始化、恢复和代码审查快照，不作为请求处理时的权威配置。

数据库目录包含能力、服务模板、发布版本和操作审计四类记录。Creator 只能选择当前版本中
`active`、允许选择且允许发布的项目；服务发布和公开请求会重新读取当前目录快照，因此暂停、
恢复、退休和紧急下架无需修改代码或重新发布前端。

## 2. 生命周期

| 状态      | Creator 选择 | 新服务发布       | 已发布服务重新检查 | 用途               |
| --------- | ------------ | ---------------- | ------------------ | ------------------ |
| `draft`   | 否           | 否               | 否                 | 编辑和待评审       |
| `active`  | 由开关控制   | 由开关和风险控制 | 是                 | 正常供给           |
| `paused`  | 否           | 否               | 否                 | 临时暂停或紧急下架 |
| `retired` | 否           | 否               | 否                 | 永久退出目录       |

`publishEnabled=false` 是独立的紧急开关，可在保留目录记录和审计的情况下立即阻止新发布、
公开展示和新的 Customer Request。恢复操作必须由 Operations 角色携带原因执行。

## 3. 权限与审计

- Creator API 只读目录快照；Creator 不能创建、修改或删除平台目录项。
- Operations API 允许修改状态、选择开关、发布开关、风险等级和发布版本。
- 每次变更必须记录操作者、原因、关联 ID、目录版本、变更前后值和时间。
- 生产环境的 Operations 凭据由部署环境提供；本地和测试环境可使用静态测试凭据。

## 4. 数据与导入

迁移 `0034_database_managed_service_policy.sql` 和 `0035_service_policy_versioned_keys.sql` 创建四张表，
并保留不同发布版本的同 ID 能力和模板行；初始迁移幂等写入 `v1` 目录。
`database/seeds/capability-service-catalog.json` 保留十个能力和十个模板，供恢复或新环境导入。
`pnpm db:seed:service-policy` 是幂等导入命令：会更新目录描述和关联元数据，不覆盖运营状态、
开关或审计历史。

发布版本前必须确保该版本的能力和模板已经导入。运行时只读取一个 `published` 版本；发布新版本
会归档旧版本，避免不同 API 请求看到不同政策版本。

## 5. 验收边界

1. 迁移可重复执行，初始目录包含十个能力、十个模板和一个已发布版本；
2. Creator 目录 API 返回数据库快照，不依赖运行时硬编码数组；
3. Operations 角色可以暂停、恢复、退休、紧急下架和发布版本，非 Operations 请求返回 403；
4. 每次管理操作都能在审计 API 查询，并包含原因、操作者、版本和前后值；
5. 能力或模板暂停后，新服务不能发布，已发布服务的公开请求被重新拦截；
6. 重复导入不会产生重复目录记录，也不会清除人工暂停或退休状态。

本决策不新增支付、结算、Marketplace、CRM、发现、AI-only 审核或新的 Canonical Event。

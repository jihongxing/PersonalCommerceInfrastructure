# PCI-PD-004 — Membership 首期切片与待裁决事项

> **状态：首期模式已推荐 / 待 Founder 裁决 / 尚未实现。**
> **依据**：[Decision 42 — FD-PCI-SCENARIO-SEQUENCING-001](../07_Product_Architecture/42_Commercial_Scenario_Sequencing_Founder_Decision.md)、[Conceptual Baseline 41](../07_Product_Architecture/41_Global_Commercial_System_Conceptual_Baseline.md) 及 PCI-PD-004 §§2–8。

## 1. 推荐首期：线下创作者空间会员

选一个由供给方自行运营的线下创作或练习空间。建议首期会员在明确的短期内可进入该空间使用公共练习区，允许多次到访，不包含单次预约、一对一服务或承诺席位。推荐在现场由供给方审核、消费者本人登录并接受已展示的条款后建立会员关系。首期建议不收费、不续期、不接入任何支付流程；这能验证加入、存续、现场资格核验和实际使用，不能验证付费意愿。

这个切片优先验证线下场景：加入与首次使用可以在现场完成，不依赖线上交付、复杂排期或长周期交付。即使期间内可多次访问，履行事实也来自每次实际入场，而不是等待整期结束后一次性标记成功。核心价值是持续会员关系与期间内访问条件，不是一次 Service 履约，也不是对作品、资产或行为的独立 Right Grant。

**以下是待批准的切片规则，不是现行产品合同，也不是对所有 Membership 的默认规则。**

| 语义                  | 首期建议                                                                                                                                                                                   |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Membership            | 在特定供给下记录供给方与 Member 的关系，分别引用现有身份并记录接受的条款版本。账号登录、C 号、昵称或联系方式都不是会员资格。                                                               |
| Qualification         | 消费者使用本人认证身份接受指定条款；获授权的供给方在现场核对并批准。两者齐备才建立关系；仅提交申请不取得资格。重复操作不重复建档。                                                         |
| Validity              | 推荐一段在接受前明示的固定期间，起点包含、终点不包含，由服务端按已接受条款判断；不以 UI 状态或运营开关代替有效性。                                                                         |
| Benefits              | 仅在显示的地点和使用条件下进入公共练习区。供给方在现场通过受保护的自身供给入口核验，消费者只能查看自身资格；无公开会员名册。给出“有资格”的结果不等于已实际入场。                           |
| Lifecycle             | 待接受或待审核不属于有效会员；在建议规则下，获批准且处于期间内才有效。到期停止核验为有效但保留历史。更正、提前结束规则待裁决；不提供转让操作，不把本切片的实现范围推广为全域不可转让规则。 |
| Transaction / Payment | 记录条款版本、参与者、消费者接受和供给方批准，关联成立的期间责任及后续使用事实。无收款就无 Payment、结算、退款或资金分录；不强建通用 Order，不将申请、批准或到期写成 Fulfillment。         |

已接受的 [Stage B 六域映射](../09_Engineering_Governance/PCI-ENG-020-Global-Conceptual-Six-Domain-Mapping.md) 支持区分关系、期间责任和实际权益使用，但属于研究依据，未决定这些规则。[D02–D04](../07_Product_Architecture/37_C5_D01_D04_Founder_Decisions.md) 与 [D05–D07](../07_Product_Architecture/38_C5_D05_D09_Founder_Decisions.md) 约束身份、领域事实和资金边界，不指定统一的可写 Order、Commitment 或 Member 表。历史 [Product Direction §10/§12](../01_Strategy/05_Personal_Commerce_Infrastructure_Product_Direction.md) 中的 Subscription / Access 对照不是首期收费或续期合同。[VS-01 PRD](../07_Product_Architecture/20_MVP_PRD_VS01.md) 明确不包含 Membership，不用于给第二场景授权或定义规则。

## 2. Founder 只需裁决本切片的商业规则

| 待决事项                   | 推荐                                                                                                                                   | 可选方案及影响                                                                                                                             |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 首期价值与是否收费         | 无费用的短期线下空间访问，按供给方在接受前展示的范围运营。                                                                             | 若首期必须验证付费，需先确定价格、收款主体、有效接受与收费争议责任；当前不接实际资金，也不把人工标记伪装成已付款。                         |
| 哪个动作使资格成立         | 消费者本人接受条款，供给方现场审核批准；不允许供给方单方面替消费者接受。                                                               | 可选自助加入，摩擦更低但改变准入责任及容量控制；或导入已有会员，需裁决外部依据和更正权，不建议纳入首期。                                   |
| 期间、提前结束与核验       | 固定期间、自然到期；仅允许供给方针对误登记作有理由、留历史的更正，不允许随意提前取消。现场核验由供给方做，实际入场另行确认。           | 可选无固定到期、按规则退出，或允许提前解除；需要另定谁能发起、资格何时终止及承诺如何处理。不把先到期或改计划条款作为已有关系的无提示重写。 |
| 暂停新加入如何处理在途申请 | Admission 默认关闭；获授权运营人员开放后才允许新加入。暂停期间可读取待处理申请，但不可批准形成新关系；已成立会员仍按原条款核验和使用。 | 如允许暂停前已接受的在途申请继续获批，需要指定可跨暂停的明确边界，不能仅凭申请创建时间推定供给方已作承诺。                                 |

不要求 Founder 选择数据库结构、URL、组件或记录形状。裁决后在实现前登记明确的领域产品合同与 `DEV-###` 变更单元，写清供给方/核验方权责、客端主体对应关系、事实来源和验收标准；不修改已冻结文件。

当前 Membership 只有 `not_integrated` 展示与服务端拒绝开启，**不存在**供给、入会、有效性、核验或会员履约闭环。现有 Admin / Service 保持原样，未新增权限、数据库授权、会话策略或 Membership 开关。

## 4. 交付切分及验收计划

- **P0（待上表裁决）**：供给方登记并发布明确条款的供给；消费者本人接受，供给方批准，持久化关系及依据；本人查看、供给方现场核验及实际入场留痕；Ops 管理开关及审计。允许已成立会员按原条款使用，不把场景状态写入会员生命周期。缺少运营集成或有效配置时不得开放新加入。校验身份与供给权限、重复接受/审批、起止点、未知资格、不存在真正入场时不得记履行、暂停/恢复、并发及重启一致性。
- **P0 验收**：在隔离 PostgreSQL、共享 API、Creator/消费者入口和现有 Admin BFF 上走完整链路：发布 → 本人接受 → 供给方批准 → 自己能查看而他人不可查看 → 现场核验与实际入场动作分别留痕 → Admin 暂停且新加入被拒、已有关系不变 → 重启后状态和审计一致 → 恢复后新加入可行。验证跨供给方拒绝、有权限角色与同源边界、其余四类未接入的场景不能开启，以及 VS-01 回归。合成测试仅证明本地链路，不是外部成员或生产运营证据。
- **P1（按首位客户反馈另行确定）**：供给方筛选和导出历史、到期提醒、受控更正的操作体验；不扩大 P0 授权或隐私边界。
- **Later（需独立批准）**：续期/付费、自动扣款、等级或权益包、转让与代理、线上交付、跨场地、积分成长；不把任何一项作为 P0 默认。

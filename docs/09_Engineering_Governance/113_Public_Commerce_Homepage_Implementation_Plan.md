# 113 — C 号公开商业主页实施计划

> 状态：本地实现及分层验证已进行；完整验收和生产条件仍有未闭合项，见第 5 节与执行台账
> 产品决策：[30 — C 号公开商业主页](../07_Product_Architecture/30_Public_Commerce_Homepage_Decision.md)
> 关联变更：DEV-061、DEV-062；执行台账：[21 — Prototype Execution](../08_Execution/21_Prototype_Execution.md)

## 1. 目标、约束与现状

交付可匿名访问的查询入口、稳定的 `/r/{C号}`、二维码、创作者主页管理和最小公开资料投影，
使访客从分享内容到已发布服务及请求形成可验证路径。沿用本地账号与 JWT，禁止引入
`apps/api-mock` 或 Supabase 认证；本地 PostgreSQL 运行和验收使用 Podman。

当前工作台读取认证后的 Identity C 号，根路径跳转登录或工作台；`/r/[commerceRef]` 有旧页面，
但其后端公开路由已注销，实际返回 `route_not_found`。旧实现读取号码记录的历史 Profile 外键，
并假设 Profile ID 等于 Creator ID，不能直接恢复。旧前端只接受 18 字符，不能处理展示用
连字符；当前服务页面使用的 Next.js 动态参数与所安装版本兼容性也须实测。`/s/{offeringId}`
及其公开 API 是单个服务入口，不能单独证明完整主页链路可用。已有分发 URL 生成器输出
`/public/{offeringId}`，而 web-v2 当前公开服务页面为 `/s/{offeringId}`；须盘点真实调用方并
处理兼容，不能将其作为已验证可用的分享入口。

DEV-061 的注册与初始化可返回 `setupPending`，不得把失败误报为成功分配。现有号码不得重新
签发，且迁移和回退不得破坏已签发号码登记簿。历史公开接口调用方及现有服务链接需盘点。

## 2. 合同与实施门禁

决策 30 第 5 节和 [PRD 的 DEV-062 修订](../07_Product_Architecture/20_MVP_PRD_VS01.md#dev-062-amendment--c-号公开商业主页)
已确定：主页可在没有已发布服务时发布并显示“尚无服务”；最后一个服务下架不改变主页状态。
主页状态独立于既有 Commerce Identity 和 Offering，暂停主页不撤下独立服务链接。
`creator_published` 沿用首次合格服务事实；`storefront_viewed` 包含成功访问已发布空主页，
不包含预览或错误。实施前仍须完成归属关联、公开字段、事件去重机制及迁移盘点；数据归属无法
证明时不得猜测或自动公开。

影响追溯：FR-001–005、FR-008–024、FR-026–027；核对 FR-025、FR-028–033 及 AT-001–AT-013
中相关公开主页、分发、请求与事件路径，逐项记录实际影响。`Generated` 不等于 `Distributed`；
预览不能产生访客浏览事件。新增规范事件或改变事件语义须先经过 DEV 与产品决策。

采用独立主页状态 `UNPUBLISHED → PUBLISHED → PAUSED → PUBLISHED`；重复命令幂等，权限、
非法转换及资料归档/失去归属须测试；服务状态保持其原生命周期。无服务时发布主页不产生
`creator_published`；无服务时访客成功打开主页产生一次 `storefront_viewed`。

## 3. 分阶段交付

### HOME-01：盘点、合同与数据设计

1. 盘点 Account、membership、Identity、Commerce Profile、`local_creator_mappings`、
   `commerce_identities` 和 `service_offerings.creator_id` 的实际关联、基数及现有调用方；验证
   多账号、多 Identity 和多 Profile 情况。不得假定 Profile ID 与 Creator ID 相等，不以邮箱
   建立归属。关联不明确时停止对相应数据的自动公开并列出待处理记录。
2. 对照已修订 PRD 和现有实现，逐项记录 FR / AT、状态和事件的代码影响，并设计视图去重和
   审计。盘点旧公开接口和服务 URL 的客户端、使用情况及兼容退出策略。
3. 明确可公开字段及编辑、选择、撤回机制，核实现有 Profile 字段与业务资料之间的映射；
   邮箱、私有资料、未选择的 Profile 默认不进入公开投影。选定 Profile 必须属于目标 Identity
   且符合生命周期与访问权限。归档当前公开 Profile 时的处理必须在状态机中明确，禁止继续
   意外公开其资料。

交付：经审阅的合同、领域不变量、真实关系图、字段清单和迁移前盘点标准；未闭合事项保持开放。

### HOME-02：持久化、迁移和回退

1. 根据关系盘点定义 Identity 到公开主页配置、所选资料和业务 Creator 的持久化方式；数据库
   强制每个 Identity 至多一个公开主页配置、选择资料归属一致，并发更新保持一致。不能借用
   号码记录上的历史 `commerce_profile_id` 作为选择依据，也不能修改号码及所有权。
2. 设计版本化迁移、索引、约束和可审计的状态更新；旧数据默认不自动公开。保留历史发布和
   分发事实；冲突、缺失关联或不能证明归属的数据列入报告，不得自动猜测、合并或暴露。
3. 迁移前备份并验证恢复，先在隔离 Podman PostgreSQL 运行空库、历史数据、冲突和失败回滚
   测试；记录迁移前后号码及历史业务数据核对。回退前冻结写入并保全迁移后签发的 C 号及新增
   状态，不能直接覆盖新号码登记簿。任何涉及真实环境的迁移均须独立盘点和验收。

### HOME-03：正式 API、授权和公开解析

1. 在领域和应用层实现号码规范化、公开解析、资料选择、预览及发布/暂停用例；在
   `apps/api` 装配 HTTP 路由与 PostgreSQL adapter。只接受 canonical 字符集的 18 位号码及
   两个规定分隔符位置，大小写及空白处理在合同中固定，非法输入不可模糊匹配。
2. 定义并版本化匿名查询合同，以及认证后的管理、预览、选择、发布和暂停合同；更新 OpenAPI、
   类型生成及兼容性清单。管理与预览通过服务端解析 Account 和 Identity 并校验权限，不信任
   调用方给出的 owner。不存在、未发布或暂停可统一为不可访问；格式错误、存储失败及上游故障
   使用可区分的错误类别。泄露与缓存策略以隐私和实时撤回为约束。
3. 面向访客只返回公开字段和属于该主页范围的已发布服务。服务详情和请求继续执行已有的
   Published / 可请求条件；暂停主页不删除历史请求或修改 Offering 状态。并发发布、暂停、
   修改资料及 Profile 归档时不得泄露已撤回资料。预览只向获授权创作者返回。
4. 为旧公开 Profile 路由制定兼容映射或明确版本化替代及退出方案；不能以旧有 ID 相等假设
   恢复路由。日志和 trace 使用路由模板，不记录邮箱、令牌、请求体或完整号码；二维码承载的
   链接不得包含会话、预览凭据或任何私有数据。限制公开查询资源消耗，具体限额和代理信任
   配置在运行设计中记录。

### HOME-04：访客入口和创作者工作台

1. 增加无需登录的公开查询路由并在网站提供可发现入口；已登录用户仍可进入工作台。输入带
   连字符或无连字符的号码，校验后跳转 canonical `/r/{18位C号}`；直接访问页面也接受两种
   输入形式并规范化到同一地址。避免将认证恢复失败解释为访客不能使用公开页面。
2. 完成公开主页：加载、格式错误、不可访问、真实故障及重试、已发布服务空态按合同区分；
   服务卡链接到已验证的详情页。核对 Next.js 当前版本的动态参数、服务端/客户端边界、元数据、
   移动端、键盘可用性及可访问性。公开响应和缓存不能在暂停、权限变更后泄露旧内容。
3. 工作台显示未发布、已发布、暂停以及加载失败与重试；提供选择公开资料、预览、发布、暂停、
   恢复、复制链接和可展示/下载的二维码。预览使用授权接口，不能生成公开预览令牌；复制失败
   应有反馈。链接和二维码使用经配置且验证的公开 Web origin；本地默认 3000，生产不得
   固定 localhost、依赖不可信 Host 或指向 API origin。不存在公网域名时只能验收本地可访问性。
4. 若调整现有服务分享路径，兼容已有已分享链接并回归生成与访问，避免破坏独立服务入口。
   视觉工作遵循 `apps/web-v2` 的 Next.js 指引与仓库 `/unslop` 规则，渲染检查覆盖桌面和移动端。

### HOME-05：验收、上线和运维

1. 分层覆盖号码格式与非法输入、状态转换、跨账号越权、Profile 归档、并发、公开字段白名单、
   发布服务过滤、缓存撤回、异常分类、二维码内容及链接规范化；数据库约束用真实 PostgreSQL
   验证。覆盖注册初始化 `setupPending` 和既有 C 号不变。
2. 在隔离 Podman PostgreSQL 和真实 `apps/api` 上执行迁移与 API 集成；用真实浏览器完成：
   注册 → 获得 C 号 → 完善资料 → 选择公开资料 → 按合同发布 → 复制链接/二维码 → 匿名
   访客粘贴号码和扫描二维码 → 主页 → 服务 → 请求 → 创作者查看请求。记录每一步可观察的
   业务结果；验证无服务发布和空态、最后服务下架后空态与主页状态不变、暂停主页后独立服务
   仍按原规则可用、恢复、修改资料、登录方式变化及刷新后地址和 C 号不变。
3. 验证无服务发布不产生 `creator_published`，首次合格服务产生一次；空主页访问产生一次
   `storefront_viewed`，预览及错误不产生，同一视图不重复记录。执行隐私/权限负向场景：
   未发布、暂停、不存在、无权限预览、其他 Identity 的 Profile、
   草稿服务、伪造二维码、数据库中断、API 500 和恢复；接口故障必须显示重试而非不存在。
   如浏览器无法直接调用相机，可解码生成图片并在浏览器打开解码 URL，再另记真实手机扫描是否
   已验证；模拟不应冒充真实外部分发。
4. 运行受影响范围格式化、lint、类型检查、单元、集成、OpenAPI、构建及相关 AT；完整
   AT-001–AT-013 仍是 VS-01 的最高验收边界。记录命令、环境、结果和既有失败，更新 DEV-062
   及每个变更单元的执行证据，不以局部成功宣称整体通过。
5. 发布前确认域名、TLS、缓存失效、限流、日志脱敏、旧链接兼容、备份恢复及回滚；仅本地环境
   时明确生产项未验证。生成二维码、复制链接或本地浏览不构成外部分发或生产可访问证据。

## 4. 完成标准

- 已确认的发布条件、状态及事件规则按 PRD 修订实现，并完成归属与字段盘点及回归验收。
- 同一 Identity 的 C 号和规范主页地址跨资料修改、暂停恢复、登录与迁移保持不变；历史号码
  和历史请求未丢失。未发布与暂停内容不可匿名访问，私有资料和未发布服务不泄漏。
- 无需登录的访客可以通过查询、链接和二维码到达同一已发布主页并完成受支持的服务请求；
  输入错误、主页不可访问和真实故障可区分，故障可重试。
- 管理、预览和公开数据边界已通过跨账号、并发与真实数据库验证；相关现有接口及事件回归通过。
- 所有验证结果和限制已登记，未完成的生产环境与外部访问条件没有被标记为通过。

## 5. 实施盘点和运行交接（2026-11-08）

### 数据归属和公开字段

本地 Account 使用 `local:<account_id>` 形式的 membership 关联 Internal Identity；一个 Identity
可有多个 membership 和 Profile。`local_creator_mappings` 把本地账号映射到业务 Creator，
`service_offerings.creator_id` 属于该 Creator。公开主页只在活跃 OWNER 对应的活跃账号映射到
唯一业务 Creator 时可解析；多个不同 Creator 或缺少映射时不猜测归属。号码经
`commerce_references.identity_id` 关联 Identity，主页配置经 Identity 和复合外键选择属于同一
Identity 的 Profile；历史号码上的 Profile 外键不用于公开选择。关联不明确的真实历史记录仍需
上线前盘点和人工处理，不能以测试数据推断生产情况。

匿名白名单只有 C 号、所选活跃 Profile 的 `display_name`，以及该 Creator 已发布且其业务
Commerce Identity 已发布的 Offering 的 `id`、`title`、`description`。注册邮箱、其他 Profile、
内部 Identity ID、草稿服务和账号资料不进入响应。资料选择、编辑和发布需要认证，Profile 归档
后解析立即不可用；修正选择后须检查主页状态。主页及预览响应使用 `Cache-Control: no-store`。

### 接口、事件和兼容

- `/api/v1/private/homepage` 及其 profile、preview、publish、pause 操作使用当前账号身份；
  `/api/v1/public/homepages/{reference}` 仅接受规范化的 C 号和 UUID 视图标识。格式错误、
  不可访问与内部故障分别返回 400、404、500；主页拒绝缓存。
- 空主页发布不写 `creator_published`；成功公开读取写 `storefront_viewed`，同一视图按
  `(correlation_id, name, object_id)` 去重；预览和不可访问不写该事件。首次合格服务发布沿用
  既有事件流程，生成二维码或链接不代表外部分发。
- 旧 `/api/v1/public/creator-profile/{commerceRef}` 此前已从正式 API 注销，仓库搜索仅发现
  无调用方的旧 hook 和未注册路由；新调用使用版本化主页接口。仓库外调用方和退出窗口尚未
  确认，上线前须通知并迁移，不能假设没有外部使用者。
- 现有分发生成器仍产生 `/public/{offeringId}`，web-v2 兼容路由转向 `/s/{offeringId}`，
  独立服务仍按原授权和服务状态规则访问。暂停主页不会修改服务或历史请求。
- 目前 Fastify 的全局限流是每个来源 IP 每分钟 100 次，默认不信任代理转发头。反向代理部署前
  必须明确可信代理和共享限额方案，并验证多实例和真实来源地址；本地结果不代表公网抗滥用验收。
  trace 使用路由模板；分享地址不得包含令牌。生产 Web origin 需配置为可信 HTTPS 域名，
  `NEXT_PUBLIC_WEB_ORIGIN` 是构建时配置；没有公网域名不能验证外部分发。

### 迁移与回退操作

迁移 0028 对号码归属、格式和一 Identity 多号码冲突执行检查，遇冲突中止；0029 建立空的主页
配置和同 Identity Profile 外键，不自动发布历史数据。上线前须备份并在隔离环境验证恢复，
盘点缺失或多重归属、记录号码及历史商业数据基线，并在事务和维护窗口内执行已审核迁移。
若需回退，先冻结写入并备份迁移后的完整数据库，保存新增 C 号、主页状态和审计，再制定并
验证保留号码登记簿的前向修复或回退脚本；不得用迁移前备份直接覆盖新增号码。针对真实数据
的冲突清理、回退脚本与演练仍需在实际目标环境完成。

本地 Podman PostgreSQL 验证过历史号码保留、冲突事务回滚、主页约束，以及测试库备份恢复后
C 号、主页和商业请求记录计数一致。该验证不证明生产备份可用，也不等于真实环境迁移。

### 需求和验收影响

FR-001–005 和 FR-008–016 保留既有身份、能力和服务生命周期，DEV-062 对 FR-005、FR-016 的
主页边界作出增补；FR-017–022 的独立服务分发、下架及历史事实保持原规则。FR-023–024 增加
显式主页发布、公开字段及空态；FR-025–033 的服务详情和请求继续使用原流程。相关自动测试及
本地浏览器链路已有证据，具体命令和缺口见执行台账；AT-001–AT-013 并未因此全部取得真实
外部服务验收。生产域名、TLS、监控告警、真实手机扫描、公网可达性和外部分发仍未验证。

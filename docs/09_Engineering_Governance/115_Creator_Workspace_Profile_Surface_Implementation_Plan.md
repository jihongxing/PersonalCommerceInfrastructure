# 115 — Creator 工作台与个人资料界面重构实施计划

> 状态：已实施；本地验收完成
> 设计决策：[32 — Creator 工作台与个人资料界面结构决策](../07_Product_Architecture/32_Creator_Workspace_Profile_Surface_Decision.md)
> 关联变更：DEV-065 / CREATOR-WORKSPACE-PROFILE-SURFACE
> 依赖决策：[30 — C 号公开商业主页](../07_Product_Architecture/30_Public_Commerce_Homepage_Decision.md)、[31 — 按日期和时间切换公开商业主页](../07_Product_Architecture/31_Time_Scheduled_Public_Homepages_Decision.md)
> 正式后端：`apps/api`；前端：`apps/web-v2`；本地 PostgreSQL 使用 Podman
> 日期：2026-11-09

## 1. 目标

将完整的对外主页管理从 Creator 工作台迁移到个人资料区域，并把管理界面拆成“当前公开状态、公开方案、自动切换、分享工具”四个层次。工作台回到日常运营首页，只显示必要摘要和入口。

本计划只涉及 `apps/web-v2` 的页面结构、组件边界、查询使用方式和交互呈现。完成后，现有后端和数据库合同继续作为唯一事实源。

## 2. 必须保持的不变量

1. 一个 Identity 只有一个终身不变的 C 号。
2. `/r/{C号}` 是唯一稳定公开入口；资料编辑、公开方案切换、时间窗口变化和登录变化不改变地址。
3. 同一时间最多公开一个主页方案；窗口无匹配时沿用既有默认主页解析规则。
4. 只有已发布主页和已发布服务进入访客公开结果；无服务时显示空态。
5. 主页发布、暂停、资料选择、预览、二维码和分享语义不变。
6. 失败响应必须继续区分认证失败、接口故障、号码格式错误、主页不可访问和正常空态。
7. 不新增数据库迁移、API 路由、OpenAPI 字段、规范事件或领域状态。

## 3. 现状盘点和目标边界

当前主页管理组件位于 `apps/web-v2/app/(creator)/dashboard/homepage-management.tsx`，被 `dashboard-client.tsx` 直接渲染；个人资料页位于 `apps/web-v2/app/(creator)/profile/page.tsx`，目前只展示资料和下一步入口。

目标边界：

| 表面                  | 重构后责任                                           |
| --------------------- | ---------------------------------------------------- |
| `/dashboard`          | 账号、C 号、资料完成度、服务和预约摘要、对外主页摘要 |
| `/profile`            | 资料 Tab 和对外主页 Tab 的容器                       |
| `/profile?tab=public` | 直接进入对外主页 Tab，支持刷新、返回和分享给本人使用 |
| `/profile/edit`       | 仅编辑商业身份资料，不承担主页发布                   |
| `/r/{C号}`            | 访客公开解析，保持既有实现和合同                     |

初期沿用既有 API：主页 Tab 使用 `/api/v1/private/homepages` 和 `/api/v1/private/profiles`，工作台摘要优先使用已有轻量配置和 C 号查询。除非实现验证发现既有响应无法支持摘要，否则不新增 summary API。

## 4. 分阶段实施

### 阶段 0：治理和基线

- 登记 DEV-065、设计决策 32 和本计划 115；
- 记录当前工作台、资料页、主页管理和公开主页的截图或浏览器验收基线；
- 建立受影响需求、接口、状态和验收映射；
- 确认当前没有未提交的用户变更被覆盖。

完成标准：计划中的文件边界明确，基线能够复现当前主页发布和时间窗口流程。

### 阶段 1：组件边界调整

- 把主页管理组件从 dashboard 目录迁移到 profile 领域目录或等价的 Creator profile surface 目录；
- 保留现有查询、mutation、错误处理、缓存失效和权限边界；
- 删除 dashboard 对完整主页管理器的直接渲染；
- 暂不改变任何 API 调用路径或业务逻辑。

完成标准：工作台不再加载主页管理器；主页 Tab 可以独立加载相同的管理功能。

### 阶段 2：个人资料 Tab 和深链接

- 在 `/profile` 增加 `资料` 与 `对外主页` Tab；
- 使用查询参数或等价的稳定路由实现 `/profile?tab=public`；
- Tab 切换不丢失认证状态，刷新后保持当前 Tab；
- 将工作台和所有主页入口统一指向对外主页 Tab；
- 保持 `/profile/edit` 的资料编辑入口和返回行为。

完成标准：直接打开、刷新、浏览器后退和从工作台进入均能落到正确 Tab。

### 阶段 3：对外主页首屏重构

- 首屏展示 C 号、稳定公开地址、当前公开资料、聚合状态和下一次切换信息；
- 将预览、打开、复制链接、二维码和发布/暂停作为主要操作；
- 无方案显示正常空态和创建入口；
- API 失败显示加载失败、错误信息和重试，不回退到空态；
- 发布操作继续显示目标资料和当前地址，避免误操作。

完成标准：用户进入页面后无需阅读全部配置即可回答“现在公开什么、地址是什么、是否已发布”。

### 阶段 4：公开方案和自动切换渐进披露

- 公开方案列表显示资料名称、方案状态、默认标记和当前激活标记；
- 创建、选择、发布、暂停、设为默认和归档按方案上下文展示；
- 自动切换作为独立区域显示窗口列表；
- 新增和编辑窗口使用集中表单，显示时区、开始时间、结束时间和启用状态；
- 继续显示服务端返回的冲突和无效时间错误；
- 预览指定方案或时间点时明确标识“预览”，不改变公开状态。

完成标准：首次进入页面不展示全部时间窗口字段；用户可以从当前状态逐步进入方案和窗口管理。

### 阶段 5：工作台摘要

- 移除完整对外主页管理区；
- 保留一段轻量状态摘要：当前状态、公开资料或空态、C 号公开地址；
- 提供“进入主页设置”和“打开主页”；
- 主页摘要加载失败时独立显示失败与重试，不阻塞能力、服务和预约入口；
- 不在工作台复制发布、暂停、二维码和窗口编辑逻辑。

完成标准：工作台首屏长度明显降低，日常入口仍完整可达，主页配置没有重复控制。

### 阶段 6：可用性和兼容性检查

- 桌面和窄屏验证 Tab、状态、操作组、方案列表和窗口表单不重叠；
- 所有按钮、Tab、表单字段和错误信息具备可访问名称；
- 验证加载中、正常空态、接口故障、认证过期、无公开主页和无服务主页；
- 验证公开链接、二维码和 C 号格式显示未变化；
- 检查没有把技术字段名直接暴露成用户必须理解的操作说明。

完成标准：UI 结构变化不会改变访客公开结果或创作者权限边界。

### 阶段 7：验证和验收

必须按变更风险运行：

- `web-v2` TypeScript 检查和生产构建；
- 受影响组件和页面的单元或交互测试；
- 主页管理 API、调度、迁移和公开解析既有测试，证明后端行为未变化；
- 浏览器验收：新用户、已有多方案创作者、发布、暂停、默认方案、时间窗口、预览、复制链接、二维码和公开访问；
- 错误验收：接口不可用、认证失效、号码格式错误、主页不可访问和无服务空态；
- `check:openapi`、格式化、Scoped ESLint、`git diff --check`；
- 更新 `docs/08_Execution/21_Prototype_Execution.md`，记录通过项、限制和未完成的生产验收。

## 5. 受影响文件和边界

预计主要涉及：

- `apps/web-v2/app/(creator)/dashboard/dashboard-client.tsx`；
- `apps/web-v2/app/(creator)/dashboard/homepage-management.tsx`；
- `apps/web-v2/app/(creator)/profile/page.tsx`；
- `apps/web-v2/app/(creator)/profile/edit/page.tsx`（仅在需要保持导航上下文时）；
- Creator 导航、页面级测试和相关共享文案或类型文件。

本计划不预期修改：

- `apps/api` 路由、应用服务、Repository 或数据库迁移；
- `contracts/api/v1` 的主页合同；
- C 号分配、公开解析、服务发布、预约和规范事件模块；
- `apps/web-v2/app/(public)` 的访客主页和服务页面。

如果实现过程中发现必须修改上述边界，必须先登记新的偏差或产品决策，不能以 UI 重构名义顺带改变后端行为。

## 6. 回退和风险

这是可通过 Git 回退的前端结构变更，不需要数据库回退或数据迁移。实施期间保留既有 API 合同和查询键，降低回退成本。

主要风险：

| 风险               | 控制措施                                                  |
| ------------------ | --------------------------------------------------------- |
| 主页配置入口被隐藏 | 工作台保留明确摘要和深链接；导航和页面测试覆盖            |
| Tab 刷新后状态丢失 | 使用 URL 状态并测试直接打开、刷新、后退                   |
| 重构时误改发布语义 | 复用既有 mutation 和 API；运行主页 API 与公开解析回归测试 |
| 工作台仍加载大数据 | 摘要优先使用轻量接口；主页详情只在 Tab 激活时加载         |
| 错误被误判为空态   | 独立断言 `isError`、重试和空数据分支                      |
| 移动端操作拥挤     | 窄屏浏览器验收和可访问名称检查                            |

## 7. 完成定义

只有同时满足以下条件才可标记完成：

1. 设计决策 32 的界面结构全部落地；
2. 工作台只保留摘要，不再渲染完整主页管理；
3. 个人资料的两个 Tab 和对外主页深链接可用；
4. 既有主页方案、发布、暂停、预览、分享和时间窗口操作全部可用；
5. C 号、公开地址、服务空态、错误分类和状态语义与重构前一致；
6. 相关自动化、浏览器、构建和治理检查通过，并在执行台账中留下证据；
7. 没有未经登记的 API、数据库、状态机或规范事件变化。

## 8. 实施记录

2026-11-09 已按本计划完成 `apps/web-v2` 界面结构重构。完整主页管理器已从工作台迁移到个人资料页，工作台保留独立加载的轻量摘要；个人资料页新增 `资料` 和 `对外主页` Tab，并支持 `/profile?tab=public` 深链接。主页设置继续复用既有查询、mutation、缓存失效、权限和稳定 C 号地址，未新增 API、数据库迁移、领域状态或规范事件。

对外主页页面现在按“当前公开状态、公开方案、自动切换、分享工具”组织。主页加载失败与正常空态分开呈现；工作台摘要失败也独立显示重试，不阻塞资料、能力和服务入口。主页管理保留单个方案预览，并提供按 UTC 指定时间解析的预览控件。新增 `profile-client.test.tsx` 覆盖深链接和 Tab URL 状态。

代码审查后补充两项边界修正：工作台将身份资料、C 号和主页摘要拆成独立查询，避免 C 号或身份接口故障吞掉主页摘要的失败/重试状态；切换公开方案时清理时间窗口编辑状态，避免继续修改上一个方案的窗口。

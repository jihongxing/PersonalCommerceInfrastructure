# PCI-ENG-020 — Founder Conceptual Decision Recommendations

> 日期：2026-11-17。WP-07；RESEARCH PROPOSAL / AWAITING MAIN CONTROLLER REVIEW。
> FR-01–FR-05 是研究建议标识，不是 FD 编号；全部 AWAITING FOUNDER DECISION WHERE REQUIRED。

## 1. 建议性质

建议依据 [Decision36](../07_Product_Architecture/36_Global_Commercial_Supply_Foundation_Decisions.md)、[D01–D04](../07_Product_Architecture/37_C5_D01_D04_Founder_Decisions.md)、[D05–D09](../07_Product_Architecture/38_C5_D05_D09_Founder_Decisions.md)、[D10–D12](../07_Product_Architecture/39_C5_D10_D12_Founder_Decisions.md)及既有研究，来源等级见[索引](PCI-ENG-020-Global-Conceptual-Source-Authority-Index.md)。这不是重新选择已批准原则；备选用于界定尚未明确的细化方式，违反现有原则的极端解释明确排除。

下述“推荐”是供 Main Controller 审阅后提交 Founder 的本轮研究建议，不冒称 Main Controller 已推荐或 Founder 已批准。每项对应[未决登记](PCI-ENG-020-Global-Conceptual-Open-Questions.md) A 类，不涉及架构方案。Founder 可以要求进一步概念研究；本文件不要求现在启动任何后续任务。

## 2. FR-01 — 六类领域的判别依据与混合表达

**问题/背景**：OQ-A01。六类独立语义已有批准，但类型重叠没有共同概念判别；按职业、页面、内容格式或收费周期分类会误把 Membership 变成支付计划、Project 变多步骤 Service。来源：F01/F03、D01/D03/D04；C4-A §7、C5 §6。

**关键边界**：领域类型表达客户获得何种价值、何种责任/权益；同一来源可以多角色使用；不决定 Offering 与领域对象基数，不证明六类穷尽。

| 候选 | 概念方向 | 影响/限制 |
| --- | --- | --- |
| A | 保留六类名称，不进一步说明判别 | 不新增原则，但混合供给归类仍模糊，后续共同关联难解释 |
| B（研究推荐） | 以被接受价值、责任方式、履行/权益意义解释领域类型；允许明确指出重叠/组合，不预设互斥或统一拆分 | 改善共同理解；具体分类边界仍需有界细化，不生成分类算法或 Template |
| C | 各领域自行判别，混合情形只保留多种专业解释及其范围，不设共同判别方向 | 保留最大自主性，但可能产生不可比较的类型声称，需要更强来源说明 |

**理由**：B 将 D03 专业语义与 D04 有类型引用连接起来，避免共同引用只剩标签；不按文件形态推定责任。**采纳后概念影响**：后续模型需要说明采用何种领域解释及原因，混合项保留未知或组合关系；不得据此强拆供给。

**明确不代表**：批准第七类型、统一分类表、多个领域对象基数、扩展现有 Template、API 或 UI。**仍需 Founder**：是否接受该判别方向；是否允许在概念层明确非互斥/非穷尽尚未证明，而不改变六类当前研究范围。

## 3. FR-02 — 有效接受与责任的共同可解释性

**问题/背景**：OQ-A02。D05/D06 禁止 Order/Payment 自动生成责任，但尚缺最小共同解释标准。来源：F01、D02/D03/D05/D06/D10；C5 §7.1。

**关键边界**：区分谁参与、谁有权接受、接受什么范围/版本、何种领域机制使责任成立；不是统一点击、签字或付款步骤。

| 候选 | 概念方向 | 影响/限制 |
| --- | --- | --- |
| A | 只引用领域“已接受/已成立”结论，不要求共同解释依据 | 对领域侵入最少，但组合关系或历史追溯可能无法理解 |
| B（研究推荐） | 在保留领域决定权前提下，要求责任解释能说明主体/代表依据、具体范围、接受依据与领域规则语境；缺少资料保持未知 | 增强共同追溯，仍不规定字段或充分证据清单；具体成立条件留领域 |
| C | 分阶段细化，只对未来跨域组合提出有界共同解释，单域先沿用既有语义 | 变更范围更小，但需清楚标记哪些关联缺少完整解释 |

**理由**：B 从“有效接受”连接到“可追溯责任”，避免有结论无根据，也不设全局接受机构。**采纳后概念影响**：未来领域说明须能回答责任依据，不能按订单行数或付款次数生成责任；原 VS-01 仅保留其已有事实，不因缺资料被判不合格。

**明确不代表**：统一 Acceptance/Commitment 实体、必填新字段、统一状态机、法律有效性认证、回填历史或修改 VS-01。**仍需 Founder**：共同可解释性是否按 B 作为未来概念约束；无法证明的代表/接受依据怎样标为未知而不补造。

## 4. FR-03 — 角色责任与权源声称的分离边界

**问题/背景**：OQ-A03。F04 已分离角色，F05/F10 及 C4-B 候选尚未裁决；模型不能借“Provider/Grantor”词汇隐含平台完成权属或资格验证。来源：F02–F04、D02/D10；C4-A §5–§6，C4-B 仅候选。

**关键边界**：参与身份、操作权限、来源控制、对外责任、上游权利、下游 Grant 分开；不确定合法权源体系或平台法律角色。

| 候选 | 概念方向 | 影响/限制 |
| --- | --- | --- |
| A | 暂停全部角色/权源细化，等待 F05/F10 独立裁决 | 最保守，但当前模型只能明示缺口，不能解释更具体责任来源 |
| B（研究推荐） | 本轮仅确认“角色声称不等于授权或权属证明；未知明确标识”的概念限制；具体权源、资格、平台责任联动提交原 F05/F10 | 防止已有词汇越权，不提前采纳 C4-B S2/P2，不扩大政策研究 |
| C | 对六类分别列出角色声称与已知依据的概念区别，跨域权源原则全部继续延后 | 能局部细化，但可能重复研究；仍不可据此冻结证明制度 |

**理由**：B 保持 F04 分离原则并正面标明缺口，避免为了完整模型把未知包装成平台认证。**采纳后概念影响**：任何角色解释注明是声称、已有依据或未知，不从创建/发布账户推出全部权利义务；具体资格仍由具名裁决处理。

**明确不代表**：重新裁决 F05/F10、Owner Anchor、Commercial Provider 实体、代理/权利链制度、平台担保、法律或政策结论。**仍需 Founder**：是否先确认该限制；F05/F10 后续应获得何种独立任务范围。没有在本轮重新开展研究。

## 5. FR-04 — 跨领域组合的依赖解释

**问题/背景**：OQ-A04。D09 同时要求保留事实和按条款解释整体后果，两者不应被误读为“全部独立”或“全部原子”。来源：D05–D07/D09/D10；C5 §10。

**关键边界**：供给、提议、交易、履行、资金五层范围可不同；关联不是自动协调规则。事实保留与未来责任后果分开。

| 候选 | 概念方向 | 影响/限制 |
| --- | --- | --- |
| A | 仅保留 D09 原则，具体依赖完全逐项解释 | 不增加规则，但共同模型仍难解释资料缺失时的关联后果 |
| B（研究推荐） | 共同解释需分别指明组成范围、接受/责任范围、已知依赖及其条款依据；缺失/冲突明确保留，不从展示/付款反推 | 使组合可解释，不给全局默认取消/退款策略；仍需具体领域条款 |
| C | 先只研究完全有界的领域关系，所有跨域整体后果暂不作进一步解释 | 避免越权，但本模型的跨域解释力明确有限 |

**理由**：B 把 D09 五层边界落实为概念审阅问题，既不抹除事实，也不否认真实条款可能产生联动。**采纳后概念影响**：后续说明整体/局部后果时必须追溯依据；未决依赖不能隐藏在总完成/总失败中。

**明确不代表**：Bundle/Package 实体、全局组合 Order/状态机、锁/事务/编排、自动补偿、退款或取消功能。**仍需 Founder**：是否采纳“依赖必须可解释，缺失不得反推”的方向；缺少条款时保留未决而不是给系统统一默认后果。

## 6. FR-05 — 不确定性、冲突与投影权威

**问题/背景**：OQ-A05。D10 已明确事实来源/解释分离，但共同展示仍可能将缺失、延迟或冲突缩成单一确定状态。来源：D07–D12，尤其 D10；C5 §8–§10。

**关键边界**：来源证据可能有多种解释，投影是“依据什么显示了什么”，不是第二份可编辑领域真相。未知、不适用、未获知不自动等于否定事实。

| 候选 | 概念方向 | 影响/限制 |
| --- | --- | --- |
| A | 只呈现专业领域的当前结论，将冲突/延迟留在专业解释中 | 表达简单，但可能误导共同视图使用者以为信息完整 |
| B（研究推荐） | 共同表达需要保留来源/范围/版本语境及已知不确定性；无法裁决时显示为未决概念，不创造全局裁决权 | 增强证据诚实性，仍未决定公开范围、界面或元数据结构 |
| C | 共同投影只表达可确认的关联存在性，不综合进度 | 权威风险低，但共同基础设施的解释力较弱；并非 D10 要求唯一方向 |

**理由**：B 维持 D10 的分工，同时避免“有来源”被简化为“最新值一定正确”。**采纳后概念影响**：模型区分来源记录、领域解释和观察表达的变化；冲突不靠覆盖解决，历史未知不被现在数据补造。

**明确不代表**：全局仲裁、证据评分/认证、数据公开权、评价申诉/删除功能、字段/API/事件、投影刷新技术或现有 UI 修改。**仍需 Founder**：是否采纳这种概念表达义务；争议/可见性细化继续 B03/B04，不立即变产品规则。

## 7. 提交与停止

Main Controller 可先对五项研究建议审阅、合并或要求补充，再决定提交 Founder 的问题。即使未来接受这些概念方向，也不自动授权架构研究、D12 验证、原型、工程或资金活动。现有 D01–D12 批准不变，新增 FR-01–FR-05 未获批准。

本轮没有将任何建议写成 FD，也没有改 PRD。交付后停止，MAIN CONTROLLER REVIEW = AWAITING；FOUNDER DECISIONS = AWAITING WHERE REQUIRED。
